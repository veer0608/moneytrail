The failure you cannot see is the one that matters

Converting a statement is easy. Knowing the conversion was complete is the hard part, and it is the part nobody does. A dropped row does not announce itself — it leaves a shorter file that balances against nothing, and the first sign of trouble is a client asking why a payment is absent three months later.

moneytrail checks every parse against arithmetic the bank already published. The running-balance column has to move by exactly the amount on each row, and opening plus credits minus debits has to equal the stated close. Both, to the paisa. If either fails you get the row number and the exact difference, before you have filed anything.

Two independent checks

The chain check finds where a fault is. The totals check finds faults the chain cannot see — including rows lost off the end.

Bound to the file, not the filename

Each certificate carries the SHA-256 of the bytes that were read. A filename says which file was meant; only a digest says which one was actually opened.

Failures are still delivered

A statement that does not add up is exported anyway, stamped, with the reason attached. Withholding it would only send you back to a converter that stays quiet.

What comes back

One workbook. Every transaction across every statement you dropped, merged in date order, with the raw narration kept beside the resolved merchant name so any row can still be found in the source PDF. Amounts are exact decimals — summing the column is the first thing anyone does, and it has to match the certificate printed beside it.

The certificate is the second sheet, in the same file. A proof that travels separately from the thing it proves gets detached on the first forward.

Built for the people doing this a dozen times a month

Accountants, bookkeepers and CA firms converting client statements by hand, or with a tool that cannot say whether it worked. If you have ever re-keyed a page of a PDF because the last conversion looked wrong and you could not prove it either way, this is for you.

It reads Indian bank and credit-card formats — the lakh grouping, the Cr/Dr suffixes, the separate withdrawal and deposit columns, the summary block bolted under the table, and the password-locked PDFs banks email out. Card statements reconcile on a different identity from bank statements, and are checked accordingly.

Your statement is not our asset

It is read inside the one request that uploads it and removed before the reply is sent. Nothing is stored, logged or queued. There is no database, so a second visit cannot see the first one's file, and there is no account for anyone to breach. The spreadsheet comes back inside that same reply and is assembled by your browser rather than fetched from a server — which is what keeps this side of it stateless.

To be exact rather than reassuring: the parsers read files, not bytes in memory, so your statement really is written to a temporary directory for the seconds it takes to parse. That directory is removed before the response is built, and there is a test asserting it.

If that is still closer than you want it, the command-line version does all of the same work without a network of any kind, and the source is public.

Questions

What if my statement does not reconcile?
You still get the spreadsheet, stamped, with the row number and the exact difference. Usually it means the parse missed something — send it over and it gets fixed, because a format that fails is a bug here, not a bug in your bank.
Which banks does it read?
The parsers work from the shape of the table rather than a list of banks, so most Indian formats work. The honest answer is that it is proven against fewer of them than it will be; drop one in and the certificate will tell you the truth either way, which is more than anything else will do.
Do you keep my licence key?
It lives in your browser and travels with each upload to be checked. There is no account behind it and nothing to reset.
Can I run it myself?
Yes. It is open source, installs with no dependencies for CSV, and self-hosting never meets the paywall.
